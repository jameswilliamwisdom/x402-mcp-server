3. **Per-wallet daily rate limiter** — thread-safe in-memory store:
   ```python
   _wallet_counts: dict = {}   # {wallet_addr_lower: (count: int, day: date)}
   _wallet_lock = threading.Lock()

   def get_wallet_address(request: Request) -> str | None:
       """Extract payer wallet from fastapi-x402 decoded_payment state.

       Structure (from fastapi-x402 0.1.8 source inspection):
       request.state.decoded_payment = {
           "payload": {
               "authorization": {"from": "0xPayerWallet", ...},
               "signature": "0x..."
           }
       }
       """
       decoded = getattr(request.state, "decoded_payment", None)
       if decoded is None:
           return None
       try:
           return decoded["payload"]["authorization"]["from"].lower()
       except (KeyError, TypeError, AttributeError):
           return None

   def check_and_increment_wallet_limit(wallet: str | None) -> None:
       """Check daily limit and increment counter atomically.
       Raises HTTP 429 if limit reached. No-op if wallet is None.
       """
       if wallet is None:
           return
       today = date.today()
       with _wallet_lock:
           count, recorded_day = _wallet_counts.get(wallet, (0, today))
           if recorded_day != today:
               count = 0  # New day -- reset
           if count >= DAILY_QUERY_LIMIT:
               raise HTTPException(
                   status_code=429,
                   detail={
                       "error": "daily_limit_exceeded",
                       "limit": DAILY_QUERY_LIMIT,
                       "resets": "midnight UTC",
                   }
               )
           _wallet_counts[wallet] = (count + 1, today)
   ```

   **CRITICAL:** Increment BEFORE calling Tavily (not after). The user paid and the attempt counts against the quota. This prevents quota manipulation via induced failures.

4. **Tavily search function** — response shaping with content -> snippet rename:
   ```python
   async def run_search(
       query: str,
       max_results: int = 5,
       include_answer: bool = False,
       include_domains: list = None,
       exclude_domains: list = None,
   ) -> dict:
       """Call Tavily and return shaped response with 'snippet' field."""
       raw = await tavily_client.search(
           query=query,
           search_depth="basic",              # Always basic: 1 credit = $0.008
           max_results=max_results,
           include_answer=include_answer,      # bool only: True or False
           include_domains=include_domains or [],
           exclude_domains=exclude_domains or [],
       )

       shaped_results = [
           {
               "title": r.get("title", ""),
               "url": r.get("url", ""),
               "snippet": r.get("content", ""),   # Rename content -> snippet
               "score": round(float(r.get("score", 0.0)), 4),
           }
           for r in raw.get("results", [])
       ]

       response = {
           "query": query,
           "results": shaped_results,
       }

       if include_answer:
           response["answer"] = raw.get("answer") or None

       return response
   ```

   **Anti-patterns to avoid:**
   - Do NOT use `include_answer="advanced"` — doubles credit cost from 1 to 2 credits, making the $0.01 endpoint price unprofitable.
   - Do NOT use `search_depth="advanced"` — same 2-credit cost problem.
   - Do NOT pass `include_answer` as string — always pass Python `True` or `False`.

5. **Lifespan context manager** — initialize AsyncTavilyClient:
   ```python
   tavily_client: AsyncTavilyClient = None

   @asynccontextmanager
   async def lifespan(app: FastAPI):
       global tavily_client
       api_key = os.environ.get("TAVILY_API_KEY", "")
       if not api_key:
           logger.warning("TAVILY_API_KEY not set — search endpoint will fail")
       tavily_client = AsyncTavilyClient(api_key=api_key)
       yield
       # No cleanup needed — AsyncTavilyClient creates new httpx session per call
   ```

   **Note:** `AsyncTavilyClient` does NOT raise at instantiation if key is invalid — it raises at first `search()` call. Validate key is non-empty at startup as a fast-fail guard.

8. **Pydantic request model:**
   ```python
   class SearchRequest(BaseModel):
       query: str = Field(..., min_length=1, max_length=400,
                          description="Search query string")
       max_results: int = Field(5, ge=1, le=10,
                                description="Number of results to return (1-10)")
   ```

   Constraints rationale:

   - Domain lists capped at 20 each (Tavily allows 300/150 but 20 is enough)

   d. **`POST /search`** — the paid search endpoint:
      ```python
      @app.post("/search")
      @pay("$0.01")
      async def search(request: Request, body: SearchRequest):
          # Per-wallet rate limit — call AFTER @pay has verified payment
          wallet = get_wallet_address(request)
          check_and_increment_wallet_limit(wallet)

          try:
              result = await run_search(
                  query=body.query,
                  max_results=body.max_results,
                  include_answer=body.include_answer,
                  include_domains=body.include_domains,
                  exclude_domains=body.exclude_domains,
              )
          except UsageLimitExceededError:
              raise HTTPException(
                  status_code=503,
                  detail="Tavily API credit limit reached. Contact service operator.",
              )
          except Exception as e:
              logger.error(f"Search failed: {e}")
              raise HTTPException(status_code=500, detail=f"Search failed: {str(e)}")

          return result
      ```

      **Decorator order:** `@app.post("/search")` outermost, `@pay("$0.01")` inner. Same as Phase 5/6 — reversing silently breaks route registration.

      **CRITICAL:** `check_and_increment_wallet_limit()` is called INSIDE the route handler, AFTER `@pay` has verified payment and set `request.state.decoded_payment`. Do NOT put this in middleware — `decoded_payment` is not available pre-payment.

**Error handling patterns (consistent with Phase 5/6):**
- Tavily credit exhausted: 503 with operator contact message
- Tavily other errors: 500 with error message
- Per-wallet limit exceeded: 429 with structured detail (error, limit, resets)
- slowapi rate limit (test endpoint): 429 from exception handler

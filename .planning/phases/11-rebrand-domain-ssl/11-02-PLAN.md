<objective>
Register usebismuth.com, configure Cloudflare Tunnel to expose it publicly over HTTPS, rebuild and redeploy the Bismuth site with the correct SITE_URL, and verify the site is live at https://usebismuth.com with no SSL warnings.

This plan has three sequential stages:
1. **Human action** — Register usebismuth.com (Namecheap or Cloudflare Registrar), point nameservers to Cloudflare, add Cloudflare Tunnel CNAME in DNS, set SSL mode to "Full"
2. **Auto** — Add usebismuth.com ingress rule to ~/.cloudflared/config.yml, reload cloudflared tunnel
3. **Auto** — Update site/deploy.sh to use SITE_URL=https://usebismuth.com, rebuild and redeploy site

CRITICAL SSL WARNING: Do NOT set Cloudflare SSL mode to "Flexible". Flexible mode + nginx serving HTTP creates an infinite redirect loop (ERR_TOO_MANY_REDIRECTS). Use "Full" mode — Cloudflare terminates TLS at the edge and forwards plain HTTP to the tunnel backend. This is correct because the tunnel runs over an encrypted connection to Cloudflare's edge regardless of the backend protocol.
</objective>

  <what-built>N/A — this is a human action task requiring domain registration and Cloudflare dashboard configuration.</what-built>
  <how-to-verify>
    Complete these steps in order:

    **Step 1 — Register usebismuth.com:**
    - Go to your preferred registrar (Cloudflare Registrar at cloudflare.com/products/registrar/ is recommended — no markup on renewal, DNS managed in same dashboard)
    - Search for usebismuth.com and register it
    - If using Cloudflare Registrar: DNS is automatically managed by Cloudflare — skip Step 2
    - If using another registrar (Namecheap, etc.): change the nameservers to Cloudflare's nameservers (you'll get these when you add the site to Cloudflare)

    **Step 2 — Add site to Cloudflare (if not using Cloudflare Registrar):**
    - Go to dash.cloudflare.com and click "Add a site"
    - Enter usebismuth.com and choose the Free plan
    - Copy the two Cloudflare nameservers shown (e.g., ada.ns.cloudflare.com and bob.ns.cloudflare.com)
    - Go back to your registrar and replace the nameservers with the two Cloudflare ones
    - Wait for propagation (usually 5-30 minutes; Cloudflare will email you when active)

    **Step 3 — Add the Tunnel CNAME in Cloudflare DNS:**
    - Go to dash.cloudflare.com → usebismuth.com → DNS tab
    - Click "Add record"
    - Type: CNAME
    - Name: usebismuth.com (or @ for root)
    - Target: 2223ce56-0bc0-4680-8778-06a5a4334c61.cfargotunnel.com
      (This is the existing tunnel UUID — same tunnel used for the crypto bot dashboards)
    - Proxy status: Proxied (orange cloud — must be ON for Cloudflare Tunnel to work)
    - TTL: Auto
    - Click Save

    **Step 4 — Set SSL mode to "Full":**
    - Go to dash.cloudflare.com → usebismuth.com → SSL/TLS tab
    - Set encryption mode to "Full"
    - CRITICAL: Do NOT use "Flexible" — it causes infinite redirect loops with nginx backends
    - "Full" is correct: Cloudflare terminates TLS at the edge, tunnels plain HTTP to the backend

    **Verification — confirm DNS is propagating:**
    ```bash
    # Should resolve to Cloudflare IPs (104.x.x.x or 172.x.x.x)
    dig usebismuth.com +short
    # Or use:
    nslookup usebismuth.com
    ```

    You do NOT need to configure anything on the home server's nginx — it already listens on port 8888 and serves the site. The tunnel handles all routing.

    **If the site shows SSL warning (ERR_CERT_AUTHORITY_INVALID):**
    - Check Cloudflare SSL/TLS mode — it may be set to "Off" or misconfigured

    **If the site shows ERR_TOO_MANY_REDIRECTS:**
    - The SSL mode is set to "Flexible" — change it to "Full" immediately
    - "Flexible" causes nginx (serving HTTP) to redirect to HTTPS, which Cloudflare then sends back as HTTP, creating an infinite loop

    **If the site shows 522 (Connection Timed Out) or 1001 (DNS resolution error):**
    - The cloudflared tunnel may not have picked up the new ingress rule
